Corrections

IRW tables are sometimes wrong: a processing script reads the wrong column, an upload doubles a table, a response is miscoded. This page states how IRW handles that, and lists corrections to published response tables.

How IRW records change

  1. Released versions do not change. Every IRW release is numbered, and the number always refers to the same data. Anything that pins a version (irw_use_version() in R, a citation) keeps getting exactly what it got.
  2. Corrections are new versions. When a table is found to differ from its source, the corrected table is published in a later release, and the earlier version stays available at its release number. Pin a version for stability; take the latest for correctness (the same rule applies to tags).
  3. Every correction is recorded. Each correction to a published response table adds a dated entry below: what changed, the IRW version in which it took effect, and the GitHub issue where it was reported.
  4. Renames and replacements point both ways. A table that replaces or is renamed from another names the table it replaces, and the replaced table’s entry names its successor.
  5. Duplicates are recorded, not adjudicated. When two tables derive from the same source, both are kept unless one is a processing error. IRW does not rank independent datasets of the same instrument or population.
  6. Withdrawals remove material from the current release onward. Material withdrawn for legal or rights reasons is removed from the current release and recorded internally; it is not listed here.
  7. IRW corrects fidelity to the source, not the source. A table is corrected when it does not match what its source released. Doubts about whether the source data are good are for the source’s authors and IRW’s documentation, not grounds for altering or flagging a table.

Corrections to item text are listed separately, on Known Issues. If you think a table is wrong, open an issue on GitHub.
